# Roles & Themes Catalog

Reference for building the role engine. Roles are listed by **mechanic** (what the engine has to do), and grouped by where they come from. Themes come later: they are reskins that rename roles and teams.

**Legend:** Team: **V** Village · **W** Wolves · **S** Solo (wins alone) · **X** changes during the game · **T** a title, not a card
When: `N1` first night only · `N` every night · `N½` every other night · `D` during the day · `†` triggers on death · `P` passive · `1×` once per game

> ⚠️ = I'm not fully sure of the official wording or which box it's in. We own only the base box, so expansion roles are written from general knowledge, not from the cards.

## 0. Decisions (2026-10-24)

- **Only the master interacts.** Phones are passive: join, hold-to-reveal the role card, and see your own status. No night actions or votes on phones, because a lit screen in a dark room gives players away, and some players have no phone. The master can add players by hand.
- **Role reveal on death is a setting** (revealed by default, as in Thiercelieux; hidden enables the Coroner, Janitor, Forger…).
- **Seating order is entered at setup.** This enables the Fox, Bear Tamer, Knight with the Rusty Sword, Empath, Chef, P.I. and Mad Bomber.
- **Narration is on-screen text only** for the master to read (no text-to-speech).
- **Information roles get their answer on the master's screen.** The master shows it to the player, e.g. turning the iPad to the Seer.

## 10. Engine primitives (to make every role above data-driven)

Every role is built from these pieces. If the engine supports them, a new role is a **config entry**, not new code.

- **Wake slot**: position in the night order, plus a condition (first night only, every N nights, only when last wolf, only after X dies).
- **Target spec**: number of targets (0/1/2/3), self allowed?, same as last night allowed?, must they be neighbours?, alive or dead.
- **Uses**: unlimited / N per game / per-potion counters.
- **Effects**: kill, protect, heal, poison, convert team, link (lovers, model, dire wolf), charm, silence, block, redirect/swap, extra votes, reveal, copy or inherit role.
- **Info outputs**: exact role, team, yes/no, count (computed from seating), list of suspects. Each has an optional "lie" modifier (Lycan, Wolf Man, Framer, Poisoner, Drunk).
- **Triggers**: on death (by cause: wolves / vote / witch / hunter), on being targeted, on another player's death, on tied vote, at dawn.
- **Statuses on players**: lover, charmed, infected, protected, poisoned, silenced, exiled, blocked, cursed, doused, revealed, vote-less.
- **Win conditions as predicates** checked after every death: team eliminated, parity reached (wolves ≥ others), everyone charmed or in the cult, lovers last two, solo-specific (voted out, target dead, survived). This is how **"is the game over?"** gets answered with no mistakes. The app can also say *who can still win*.
- **Settings**: roles revealed on death or hidden, Sheriff on or off, Witch may self-heal, Piper charms 1 or 2, Little Girl rules, event deck on or off, seating order (needed for the Fox, Bear Tamer, Knight, Empath, Chef).

## 12. Notes from codemafia (what to reuse, what to change)

- **Reuse**: the PartySocket client manager (connect, queue, reconnect), the Next 16 + React Compiler + Tailwind 4 + Zustand setup, and the host check (`isHostSender`).
- **Change: secrets.** codemafia broadcasts the **whole** state to every connection. Werewolves needs a **per-player filtered view**: a phone only receives its own role and what it's allowed to know. The master view gets everything.
- **Change: refresh survival.** `onClose` removes the player. Instead, keep players on disconnect and mark them "offline". The phone keeps a `playerId` plus a secret token (cookie or localStorage) and re-joins with it.
- **Change: persistence.** State lives only in memory. Use `room.storage` so a game survives server hibernation or redeploys.
- **Rollback**: model the game as an **append-only log of master actions** (`state = reduce(log)`). Undo removes the last action and replays the log. This also gives a full game history for the end screen.
